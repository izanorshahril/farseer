## Design Specificity Verdict

Authored for this product, decisively. The refusals are the evidence: `Meter` accepts only a provider-stated percent so farseer cannot render one it computed; cost is labelled "at list price, not billed" per runner; `confirmVerb` singles out `cancel` because of the run state model, not a blanket delete rule.

Deterministic scan: `detect.mjs --json ui/src` returned `[]`, exit 0. Browser measurement at 1600x1000 and 900x700: 0 text under 11px, 0 contrast failures, 0 targets under 24px, 0 unnamed inputs, no horizontal overflow, no console errors.

One reported finding was a false positive: "no focus indicator on 12 tabbables". Scripted `.focus()` does not satisfy `:focus-visible`, which is what the rule keys on. The rule is present and correct - forced application computes `rgb(88, 166, 255) solid 2px`.

## Priority Issues

- **[P1] Raw stderr rendered as manager speech.** A run that died before the model spoke ended with farseer's error as its text, under "top manager". Fixed: a third speaker, `farseer`, in `conversation.tsx`; text kept verbatim.
- **[P1] Withdrawing a root did not clear a project selected inside it.** The failure arrived one instruction later, detached from the click. Fixed in `projects.tsx` with the aftermath named in the dialog.
- **[P2] Two divergent confirm() call sites.** Fixed: `confirmGrantWithdrawal` in `confirm.ts`.
- **[P2] No filter past ~12 projects.** Fixed: a filter appears above `FILTER_AT`.
- **[P3] Vocabulary taught on one widget, used on three.** Fixed: `meaning.ts`, reused in Delegation and Projects.

## Not fixed

- No reorder or hide for roots.
- Runs does not distinguish manager from worker at a glance the way Runners does with tree indentation.

## Since fixed, 2026-08-31

The three above, in the order they were built.

- **Runs now indents a worker under its manager**, the same idiom Runners already used - `threaded()` in `runs.tsx` groups by `task_id`, keeps the API's task order, and sorts oldest-first inside one task so the manager comes before what it handed off. The indent reads `role` from the record rather than position in the list: a worker whose manager fell outside the 25-run window renders flat, because indenting it under the row above would name a manager that is not there. Rows that are not indented carry the role as a badge.
- **Roots reorder and fold.** Two one-glyph controls on the root's own line, persisted through `ui-state/projects` as `{ order, collapsed }` per `24 ui state persistence`. Fold hides a root's *projects* and never the root: a grant the operator cannot see is a grant they cannot withdraw. A move writes back the whole displayed order, so a list holding roots nobody arranged comes out of one click fully ordered. Withdrawing a root prunes both lists.
- **A keyboard path.** The canvas grip is focusable and answers arrow keys with the move the drop performs; React reconciles the section by key, so focus travels with the card and repeats. Each root's project chips are one tab stop with roving arrows, Home and End - two dozen chips were two dozen tab stops between the operator and the field below them, and the stop starts on the project already chosen.

Verified in the browser by measurement rather than by screenshot, which this environment renders unreliably at emulated sizes: grip focus moves Conversation past Delegation and back with focus retained; arrows walk 25 chips with exactly one `tabIndex=0` following the cursor; a fold survives a reload; a second root added and withdrawn again moves up, disables its end buttons correctly, persists the whole order, and leaves the arrangement pruned. `detect.mjs --json ui/src` is `[]`, exit 0; no overflow at 1600x1000 or 900x700; the new controls measure 26x24.
